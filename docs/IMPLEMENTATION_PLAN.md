# 实施计划

本文档根据 `docs/PROJECT_REQUIREMENTS.md` 中的真实需求拆分开发阶段。当前已完成阶段 4 基础实现：B站输入解析、视频信息与字幕处理代码已接入，但真实 B站请求在当前环境遇到 HTTP 412 风控风险。经过本机验证，普通 yt-dlp 匿名请求、`--impersonate chrome` 和 `--cookies-from-browser chrome` 均未形成稳定可用路径，因此项目路线明确为本地桌面运行优先。下一步进入阶段 4.1：本地桌面启动版与自动环境准备。后续实现必须继续按阶段推进，不得越过当前阶段直接实现后续链路。

## 项目定位

目标是实现一个下载 zip 后可在 Windows / Mac 桌面本地启动的 B站视频转文字小型 Workflow / 小型 Agent 项目。

核心形态：

- 后端：Python FastAPI。
- 前端：原生 HTML/CSS/JS，阶段 1 已确认。
- 运行：本地 zip 启动版为主交付形态，用户可在 Windows 或 Mac 上双击脚本启动本地服务。
- 数据：无登录、无服务端数据库，用户配置和历史结果全部保存在浏览器 IndexedDB。
- 核心链路：B站输入解析、视频信息获取、本地 zip 环境准备、本地 B站高级访问模式、字幕获取与清理、音频下载、MP3 转换、长音频切片、第一模型音频转写、第二模型文稿优化、Markdown 展示与下载、历史保存。

## 阶段 4：B站输入解析、视频信息与字幕处理

目标：完成 B站单视频和当前分P的基础解析、信息获取、字幕获取与字幕清理。

主要任务：

1. 实现从普通 B站网址、完整分享文本和 BV 号中提取视频标识。
2. 使用 yt-dlp 获取视频标题、BV 号、P 序号、分P列表、时长等信息。
3. 支持普通单视频和当前分P处理。
4. 识别多P或多视频列表时，为后续多子任务预留数据结构。
5. 尽量获取 B站自带字幕，包括 UP 主上传字幕和自动字幕。
6. 字幕语言优先级：中文优先，其次英文。
7. 清理 WEBVTT 字幕：删除头、时间轴、纯数字序号、空行、NOTE、STYLE、REGION 等元信息，保留正文顺序。
8. 支持 JSON 字幕正文抽取，并按时间顺序排列。
9. 区分字幕失败原因：无字幕、超时、格式无法解析、B站返回异常、yt-dlp 或内部错误。
10. 构建统一弹窗样式，弹窗UI也是与ChatGPT相似的UI设计。
11. 前端在字幕失败时弹出明确提示，并允许用户选择跳过字幕继续。

完成标准：

- 完整分享文本中的 B站网址或 BV 号可以被正确识别。
- 后端可以获取单视频或当前分P的视频信息。
- 有字幕时可以得到清理后的纯文本字幕。
- 无字幕或字幕失败时，错误原因明确，并支持跳过字幕进入后续流程。
- 多P结构有清晰 TODO 或模块入口，且不会把多个视频合并成一份文稿。

## 阶段 4.1：本地桌面启动版与自动环境准备

目标：全力开发本地运行形态，让普通用户下载 zip 到 Windows 或 Mac 后，通过启动脚本自动准备环境、启动本地服务，并在浏览器打开 `http://127.0.0.1:8000` 使用同一套项目能力。

路线调整依据：

1. 真实公开视频在普通 yt-dlp 匿名请求下返回 `HTTP 412 Precondition Failed`。
2. 安装 `curl_cffi` 并使用 `yt-dlp --impersonate chrome` 后仍返回 `HTTP 412 Precondition Failed`。
3. 使用 `yt-dlp --cookies-from-browser chrome` 时，在当前 Windows / Chrome 环境中返回 `Could not copy Chrome cookie database`。
4. 因此，后续投入集中在本地桌面启动和本机访问能力。

约束：

1. 阶段 4.1 只解决本地启动、环境检测、依赖准备和本地服务启动。
2. 不得提前实现音频下载、MP3 转换、音频切片、模型转写或最终 Markdown 生成。
3. 不得把手动复制 B站 Cookie 作为普通用户启动或基础使用的前置条件。
4. 阶段 4.1 只围绕本地运行，不引入远程运行链路。

主要任务：

1. 设计本地 zip 目录结构，例如 `scripts/`、`runtime/`、`data/`、`logs/`、`start-windows.bat`、`start-mac.command`。
2. 创建 Windows 启动脚本。
3. 创建 Mac 启动脚本。
4. 启动脚本先检测本机是否已有可用 Python。
5. Python 检测只要求存在可用 Python，不强制固定小版本；但如果没有 Python，优先下载 Python 3.12 系列运行时。
6. Python 下载来源优先考虑官方 CPython GitHub Releases 或 Python 官方下载地址；实现阶段必须验证 Windows 和 Mac 是否存在可直接安装或解压的官方二进制包，不得使用来路不明镜像。
7. 启动脚本检测 FFmpeg 是否可用。
8. 如果没有 FFmpeg，自动下载并解压 FFmpeg 到项目可控目录或用户本地应用数据目录。
9. 建立本地虚拟环境或等价隔离依赖目录。
10. 自动安装后端依赖，包含 yt-dlp、FastAPI、Uvicorn、httpx，以及阶段 4 已经需要的字幕和 B站处理依赖。
11. 自动启动 FastAPI 服务。
12. 自动打开默认浏览器访问 `http://127.0.0.1:8000`。
13. 如果 8000 端口被占用，自动选择下一个可用端口，并打开对应 URL。
14. 在控制台输出清晰状态：检测 Python、检测 FFmpeg、安装依赖、启动服务、打开浏览器。
15. 启动失败时给出明确错误和下一步建议。
16. 本地运行产生的临时音频、字幕、日志和依赖缓存必须有清楚目录边界。
17. README 增加“下载 zip 本地运行”说明，面向普通用户写清楚双击启动流程和常见问题。

完成标准：

- Windows 用户下载 zip 后，可以通过一个启动脚本完成环境检测、必要下载、依赖安装、服务启动和浏览器打开。
- Mac 用户下载 zip 后，可以通过一个启动脚本完成环境检测、必要下载、依赖安装、服务启动和浏览器打开。
- 本机已有 Python 时，不重复强制安装 Python。
- 本机没有 Python 时，脚本会下载 Python 3.12 系列官方运行时或给出明确失败提示。
- 本机没有 FFmpeg 时，脚本会下载并配置 FFmpeg，或给出明确失败提示。
- 如果 8000 端口被占用，脚本会自动使用可用端口并打开正确 URL。
- 启动过程的控制台提示适合普通用户理解。
- 本地 zip 版仍使用同一套前后端代码，不产生独立分叉。
- 阶段 4.1 没有提前实现阶段 5 及后续链路。

## 阶段 4.2：本地 B站高级访问模式

目标：在本地桌面版已经可以启动的基础上，专门解决 B站公开视频信息和字幕读取受 HTTP 412、浏览器 Cookie 读取失败、风控策略变化影响的问题，尽量为普通用户提供可理解、可选择、可排错的本地访问方案。

产品定位：

1. 阶段 4.2 只服务本地桌面运行版。
2. 本地 B站高级访问模式不是独立版本，而是同一项目中的可选能力。
3. 不承诺所有 B站视频都能处理；付费、会员、登录限制、区域限制、版权限制或 B站风控拦截都需要明确提示。
4. 普通用户不应被要求理解 Cookie 才能启动项目；高级能力必须有清楚按钮、说明和失败提示。

主要任务：

1. 梳理当前阶段 4 的 yt-dlp 请求策略，记录普通匿名请求、请求头增强、`impersonate chrome`、`cookies-from-browser chrome` 的已验证失败结果。
2. 在后端建立本地访问策略枚举，例如 `anonymous`、`impersonate`、`browser_cookie`、`cookies_file`、`local_browser_profile`。
3. 保留标准匿名请求和增强请求头作为第一层尝试，但不再把它视为足够可靠的主方案。
4. 保留 `curl_cffi` / `--impersonate chrome` 作为轻量尝试路径，并在失败时明确记录 HTTP 412。
5. 评估并实现可选的浏览器 Cookie 读取能力，支持 Chrome、Edge、Firefox 等来源；必须由用户明确选择。
6. 对 `Could not copy Chrome cookie database` 这类错误提供明确提示：关闭浏览器、关闭后台进程、换用 Edge / Firefox、或使用其他高级模式。
7. 评估并实现导入 `cookies.txt` 的高级用户兜底能力；不得把 cookies 文件内容写入日志或 IndexedDB。
8. 评估本地专用浏览器登录窗口或本地持久浏览器 Profile 方案；如引入 Playwright、Puppeteer、Chromium 等能力，只允许用于本地版，并必须单独评估体积、首次下载、启动速度和用户授权提示。
9. 前端提供“B站访问模式”或等价设置入口，默认使用自动模式，高级选项折叠隐藏。
10. 任务日志记录当前访问策略和失败原因，但不得记录 Cookie、token、浏览器 Profile 路径中的敏感信息或完整请求头。
11. 对 HTTP 412、403、404、超时、网络错误、yt-dlp 内部错误、Cookie 数据库复制失败、Cookie 无效等做更细分类。
12. 字幕失败弹窗保留跳过字幕继续的能力。
13. README 增加本地 B站访问排错说明，解释 HTTP 412、Cookie 读取失败和不同高级模式的适用场景。

完成标准：

- 后端可以按自动策略尝试普通匿名、增强请求头、浏览器指纹模拟和用户选择的本地高级模式。
- 对真实公开视频，如果普通请求仍返回 HTTP 412，前端能给出明确说明和下一步选择。
- `cookies-from-browser` 失败时，前端不显示笼统内部错误，而是提示浏览器 Cookie 数据库复制失败及可尝试动作。
- 如实现 `cookies.txt` 导入，Cookie 内容不进入日志、IndexedDB 或后端持久文件。
- 如实现本地浏览器 Profile 方案，登录态只保存在用户本机可控目录，并有清楚隐私提示。
- 任务日志能帮助排查访问策略，但不会泄露 Cookie、token 或敏感路径。
- 阶段 4.2 没有提前实现阶段 5 及后续链路。

## 阶段 5：音频下载、MP3 转换与切片

目标：完成后端音频处理链路，确保只处理音频临时文件，不依赖后端长期存储。

主要任务：

1. 使用 yt-dlp 只下载音频，不下载完整视频。
2. 使用安全文件名，过滤系统不允许的字符。
3. 每个任务使用独立临时目录。
4. 使用 FFmpeg 将音频统一转换为 MP3。
5. 识别需要登录权限、付费或受限内容，并给出 MVP 不支持的明确错误。
6. 对短于或等于 20 分钟的音频不切片。
7. 对超过 20 分钟的音频进行切片。
8. 切片目标长度约 20 分钟，优先在 18 到 22 分钟范围内寻找静音点。
9. 找不到静音点时按 20 分钟硬切。
10. 切片文件按 `part_001.mp3`、`part_002.mp3` 编号。
11. 日志记录切片数量、每段时长和切分位置。
12. 下载、转换、切片失败时写入明确错误和日志。

完成标准：

- 后端能下载可访问 B站视频的音频。
- 后端能把音频转换为 MP3。
- 长音频能按规则切片，并按编号输出。
- 任务完成、失败或取消后会清理临时音频目录。

## 阶段 6：第一模型音频转文字

目标：调用第一个 OpenAI-compatible Chat Completions 多模态模型，将 MP3 切片转成完整 AI 音频转文字稿。

主要任务：

1. 封装音频模型客户端模块，例如 `llm_client.py` 或 `transcription_client.py`。
2. 使用用户配置的 API Base URL、API Key、Model、Temperature、Stream。
3. 将 MP3 以常见 `input_audio` / base64 mp3 方案构造 payload。
4. 将 payload 构造放在独立函数中，方便适配不同服务商。
5. 对每个音频切片按编号调用模型。
6. 第一个片段开始后，每隔 10 秒启动下一个片段请求。
7. 单任务内片段请求并发上限默认 2。
8. 每个片段最多自动重试 3 次。
9. 区分并记录 API 超时、限流、格式错误、模型不支持音频、鉴权失败、网络错误、空内容等原因。
10. 任一片段 3 次失败后，任务失败，并向前端展示该片段失败原因。
11. 所有片段成功后，按编号顺序合并为完整 AI 音频转文字稿。
12. 合并时只做简单去重和段落修整，不额外调用模型清理每段结果。

完成标准：

- 单段 MP3 可以调用第一个模型得到文本。
- 多个切片可以并发受控地转写并按编号合并。
- 模型调用失败时错误明确，且不会泄露 API Key。
- 前端可以看到当前切片进度，例如 `part_001 / part_003`。

## 阶段 7：第二模型文稿优化与 Markdown 输出

目标：将清理后的 B站字幕和 AI 音频转文字稿合并优化为最终干净 Markdown 文稿。

主要任务：

1. 在 `prompts.py` 或等价常量文件中保存第二模型内置提示词。
2. 调用第二个 OpenAI-compatible Chat Completions 模型。
3. 输入结构包含 `<YourTask>`、`<OriginalSubtitleContent>`、`<AIAudioTranscriptionResult>`。
4. 无字幕且用户选择继续时，按需求填入“该视频没有自带字幕，请根据 AI 音频转文字的结果进行优化。”
5. 清理模型输出中的 `<think>...</think>` 内容。
6. 删除残留 `<think>`、`</think>` 标签和 `KINGFALL MODE ENABLE` 字样。
7. 最终只保留干净 Markdown 正文。
